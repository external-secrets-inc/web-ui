# DataTable Component

<Description of={DataTableStories} /> {/* Pulls description from CSF meta (if any) or use markdown */}

Renders data provided by the parent `<DataProvider>` in a standard HTML table format.

**Features:**
- Sorting (Click headers)
- Row Selection (If `onRowClick` is provided)
- Virtualization (Static, Dynamic, Window)
- Sticky Header (Automatic for table scroll, configurable for window scroll)
- Customizable row actions via `meta` prop

## Primary Story (Static Virtualization)
This is the recommended and most performant virtualization mode for large datasets with fixed row heights.

## Virtualization Modes

### 1. Static Mode (`virtualizationMode="static"`) - Recommended
- All rows have the same fixed height (set via `rowHeight` prop).
- Most performant option.
- **Requires:** The `<DataTable>` or a parent must have a defined height (e.g., `h-[400px]`)

<Canvas of={DataTableStories.StaticVirtualization} />

### 2. Dynamic Mode (`virtualizationMode="dynamic"`)
- Rows can have variable heights.
- Requires `estimateSize` function via `virtualizerOptions` prop.
- More flexible, slightly less performant.
- **Requires:** The `<DataTable>` or a parent must have a defined height (e.g., `h-[400px]`)

<Canvas of={DataTableStories.DynamicVirtualization} />

### 3. Window Scrolling Mode (`virtualizationContainer="window"`)
- Uses the browser window as the scroll container.
- Useful for full-page tables.
- Can be used with Static or Dynamic row heights.
- Ignores `className` height on `<DataTable>`.
#### Sticky Header Offset (Window Mode Specific)
- Header isn't sticky by default (shares window scroll).
- To make it sticky & account for fixed elements above (e.g., site header), set `--window-container-header-offset` CSS variable to their combined height.
- Apply via `style` prop (`style={{ "--window-container-header-offset": "64px" }}`) or Tailwind arbitrary class (`className="[--window-container-header-offset:64px]"`) on `DataTable` or a parent.
