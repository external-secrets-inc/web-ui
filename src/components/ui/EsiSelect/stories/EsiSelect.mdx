# EsiSelect Component

<Description of={EsiSelectStories} />

Searchable Select supporting both multiple and single modes. Multiple mode retains grouping, tri-state group toggles that respect the current filter, and badge overflow handling via a compact "+N" counter with tooltip. Single mode removes checkboxes/toggles and shows a right-aligned checkmark on the selected row.

## Context and Design

- **Search behavior**: uses CMDK's `defaultFilter` but matches against option labels only (IDs are used strictly for identity/hover stability).
- **Group toggles**: each group heading renders a checkbox (checked/indeterminate/unchecked). Toggling affects only items visible under the active search.
- **Overflow badges**: selected values render as badges; overflow collapses into a counter badge with a tooltip listing hidden selections. Wrap stories/apps with `<TooltipProvider/>`.
- **Customization**: customize selected badges and option rows without breaking truncation.
- **Accessibility/UX**: keyboard navigation via CMDK; Tooltip semantics via Radix.

## Import

```tsx
import { EsiSelect } from '@/components/ui/EsiSelect';
```

## API Highlights

### Core Props
- `options: { label: string; value: string; icon?: React.ComponentType; group?: string }[]`
- **Multiple mode**: `mode="multiple"`, `onValueChange(values: string[])`, `defaultValue?: string[]`, `maxCount?: number | 'auto'`
- **Single mode (default)**: `mode?: 'single'`, `onValueChange(value: string | null)`, `defaultValue?: string | null`

### Customization Props

#### Option Customization
- `renderOption?(ctx)`: custom row content with full control over layout and styling
- `optionItemClassName?`: simple className override for option rows
- `optionItemProps?`: customize option row surface properties (static or per-option function)

#### Badge Customization (Multiple Mode Only)
- `selectedBadgeProps?`: customize badge appearance (static or per-option function)
- `renderSelectedBadge?(ctx)`: custom badge content layout with full control
- `selectedExtraBadge?`: customize the "+N more" counter badge
- `selectedBadgeGroupClassName?`: customize the BadgeGroup container

#### Trigger Customization (Single Mode Only)
- `renderSelectedTrigger?(ctx)`: custom single mode trigger display
- `selectedTriggerProps?`: customize single mode trigger surface properties

## Customization Patterns

### Value-or-Function Props
Many customization props accept either a static value or a function that receives context:

#### Static Values
```tsx
selectedBadgeProps={{ variant: "outline", className: "bg-blue-100" }}
selectedTriggerProps={{ className: "bg-green-50 border-green-200" }}
optionItemProps={{ className: "hover:bg-blue-50" }}
```

#### Dynamic Functions
```tsx
selectedBadgeProps={(option) => ({
  className: option.group === "Team" ? "bg-blue-100" : "bg-gray-100"
})}

selectedTriggerProps={(ctx) => ({
  className: ctx.option.group === "Engineering" ? "bg-blue-50" : "bg-gray-50"
})}

optionItemProps={(ctx) => ({
  className: ctx.isSelected ? "bg-primary/10" : "hover:bg-muted/50"
})}
```

### Context-Aware Rendering
Custom render functions receive rich context for sophisticated customization:

```tsx
renderSelectedBadge={({ option, labelNode, iconNode, removeNode }) => (
  <div className="flex items-center gap-2">
    {iconNode && <div className="w-4 h-4 text-blue-600">{iconNode}</div>}
    <span className="font-medium">{labelNode}</span>
    <Badge variant="outline">{option.group}</Badge>
    {removeNode}
  </div>
)}

renderSelectedTrigger={({ option, iconNode }) => (
  <div className="flex items-center gap-2">
    {iconNode && <div className="w-5 h-5 bg-blue-100 rounded-full">{iconNode}</div>}
    <span>{option.label}</span>
    <Badge>{option.group}</Badge>
  </div>
)}
```

## Filtering Model

Fuzzy matching delegates to CMDK's `defaultFilter`, but it runs against `option.label` exclusively. Option `value` is used for identity and stable selection/hover.

## Group Tri‑State Logic

Group checkbox state is derived from the set of currently visible items in that group under the active search:

- **checked**: all visible group items selected
- **indeterminate**: some but not all visible group items selected
- **unchecked**: none of the visible group items selected

Toggling selects/deselects only those visible items.

## Overflow Details

In `auto` mode, a resize observer determines how many badges fit without wrapping; overflow collapses into an extra counter badge with a tooltip. Wrap with `<TooltipProvider/>`.

### Overflow Modes
- **`maxCount: "auto"`**: Dynamically calculates how many badges fit, shows "+N more" for overflow
- **`maxCount: number`**: Fixed limit, shows exactly N badges + "+N more" counter
- **`maxCount: undefined`**: Shows all badges (may wrap to multiple lines)

## Controlled Single Value: null vs empty string

- In single mode, the `value` prop has three distinct meanings:
  - `undefined`: uncontrolled (component manages its own selection)
  - `null`: controlled empty (clears the selection)
  - `""` (empty string): a valid selected value (useful when your domain treats empty as a real option)

See the "Controlled vs Uncontrolled (Normalization)" story below to see these behaviors in action.

## Controlled vs Uncontrolled (Normalization)

Internally, EsiSelect normalizes selection state to an array of strings (`selectedValues: string[]`) to keep behavior consistent across modes:

- Multiple mode
  - `value === undefined` → uncontrolled (component manages selection)
  - `value === []` → controlled empty (cleared)
  - `value === [..]` → controlled selected values
- Single mode
  - `value === undefined` → uncontrolled
  - `value === null` → controlled empty (cleared)
  - `value === string` (including `""`) → controlled selected value

See the "Controlled vs Uncontrolled (Normalization)" story for hands-on examples.
